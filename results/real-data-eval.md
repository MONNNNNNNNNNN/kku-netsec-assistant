# NetSec Board on real systems and real data (7 November 2026)

Before this round, every integration had been tested only against mocks written from vendor documentation, and no real LLM had ever run inside the board. This report records what changed when the board met real software and real data, and what had to be fixed. Every number below comes from a JSON file in [`results/real-data/`](real-data/), produced by a script in [`lab/`](../lab/) that anyone can re-run (see [`lab/README.md`](../lab/README.md)). Real traffic from this VM is published as aggregates only. Screenshots are masked before the board renders them.

## Setup

| Component | Version / source | What is real |

## Defects that only real systems exposed (all fixed, each with a regression test)

| # | Found by | Defect | Fix | Before → after |
|---|---|---|---|---|
| R1 | X1, BOTSv1 | The "long base64 blob" injection rule matched every long URL path (`/` is a base64 character) and every OCSP request (base64 DER) | flag base64 only when it decodes to prose | 851 → 0 false flags; 933 → 145 cards; recall on the project's injection samples unchanged |
| R2 | X1 | Hypothesis: app-control severity should use `apprisk`. **Refuted**: 116,863 benign lines carry `apprisk=elevated`; the Cerber C2 lines carry `crlevel=critical` | kept `crlevel`, documented | n/a |
| R3 | X4, Zabbix 7.0.32 | `event.get` never requested `value`; real Zabbix returns only requested fields, so **no recovery ever resolved a card** in pull mode. The mock returned every field and hid it | request `value`; the mock now honours `output` (and refuses `apiinfo.version` with an auth header, as 7.0 does) | recovery: never → 6.0 s |
| R4 | X4 | First pull: the open-problem seed was applied before older history of the same trigger, so a problem that flapped within the lookback showed **resolved while open** | apply everything fetched in eventid order | recovery measured as 0 ms (wrong) → 6.0 s |
| R5 | X5 | A 3B model on CPU answered only 4 of 11 cards in batches of 5 | default batch 1, budget 12 calls/hour | 36% → 100% verdicts, 85.6 → 22.9 s per call |
| R6 | X2 setup | The setup wizard had no CA question; Wazuh's indexer CA is self-signed, so the live test could never pass | ask for a CA file for https (default `/etc/netsec-board/wazuh-root-ca.pem`) | fail → ok |
| R7 | X2 | An indexer short of heap answers every query with HTTP 429 `circuit_breaking_exception`; the board showed only the raw error | explain the cause and the `jvm.options` fix (board and setup) | raw 429 → actionable message |
| R8 | X3 | Suspected: the hook rate limit (120/min) drops real Wazuh pushes. **Refuted at real rates** (0 rejected of 438) | kept the limit; rejected posts are now counted on the hook tile | n/a |
| N1 | screenshots | Cloud masking replaced short names inside words (user "old" turned "folder" into "fUSER_1er") | replace whole names only | n/a |
| C9 | review | An install from a clone tarred the whole working tree, including `lab/data` (lab secrets) and the 500 MB BOTSv1 download | package `git ls-files` only | app 500+ MB → 3.2 MB |
| K1 | scoring review | An acknowledged card of an event that never resolves (FortiGate, Wazuh) stayed silent forever: repeats keep the ack | a repeat after 24 h of quiet re-arms the card (`board.rearmAfterHours`) | silent forever → notified again |
| K2 | scoring review | Operators could not tune severity per rule (e.g. FortiOS logs every config change as `alert` → critical) | `severityOverrides`, matched on device-generated fields only; a flagged event stays ≥ medium; `check` validates | n/a |
| K3 | real screenshot | Internet SSH scanning (Wazuh 5710, low) made one card per attacker IP | low alerts group per rule and agent, IPs kept as samples; medium+ stay per source (`perSourceCardsFrom`) | real 3 weeks: 151 → 57 cards; host SSH scanning 22 → 1 card |

Also found and fixed in the lab tooling itself:
- Two harness bugs. `spawnSync` froze the in-process board during an attack. A "last N alerts" diagnostic window was hidden by a noisy Windows agent.
- Two setup details. A Zabbix media type created through the API is disabled by default. Wazuh 4.14's default agent config reads sshd from journald, not `/var/log/auth.log`.

## Limits (what this does not show)
- **FortiGate**: BOTSv1 is FortiOS 5.x from 2016, not KKU's FortiOS version or device; no real FortiGate sent syslog or answered REST here. Whether current FortiOS escapes quotes inside fields (finding D1) is still unverified.
- **One VM, one site**: Wazuh is a release-candidate build; KKU's own Wazuh and Zabbix (versions, rule sets, volumes) were not tested; no multi-node scale test.
- **Lab bias**: the lab attacks are ours and loud; the live internet traffic is SSH scanning only.
- **Compressed replays**: card counts from replays that compress time (X2 history) overstate burst cards; the X1 timeline replay uses event time and is the representative figure.
- **LLM**: one 3B model on one CPU; 11 cards per setting is a small sample.
