0 คู่มือนี้คืออะไรAbout this manual

NetSec Board คือกระดานติดตามเหตุการณ์ด้าน network และ security ที่ดึงข้อมูลจาก FortiGate, Wazuh และ Zabbix มาเองโดยอัตโนมัติ แสดงเป็นการ์ด และแจ้งเตือนเมื่อมีเรื่องสำคัญ ทำงานใน on-prem อ่านข้อมูลอย่างเดียว ไม่เขียนกลับไปที่อุปกรณ์

NetSec Board is a monitoring board for network and security events. It pulls and receives data from FortiGate, Wazuh and Zabbix automatically, shows each event as a card, and notifies people when something matters. It runs on-prem and only reads; it never writes to a device.

  • ผู้ปฏิบัติงาน (operator): อ่านส่วน "ใช้งานประจำวัน" ทุกอย่างที่ต้องทำบนกระดานอยู่ที่นั่นOperators: read "Daily use": everything you do on the board is there.
  • ผู้ดูแลระบบ (admin): อ่านส่วน "ติดตั้งและตั้งค่า" และ "แก้ปัญหา"Admins: read "Install and configure" and "Troubleshooting".
  • ตัวเลขทั้งหมดในคู่มือนี้วัดจากระบบจริง ดู results/real-data-eval.mdEvery number in this manual was measured on real systems: see results/real-data-eval.md.

2 ใช้งานประจำวัน 2: ระดับความรุนแรงDaily use 2: what the severity means

ระดับมาจาก field ที่อุปกรณ์สร้างเองเท่านั้น ข้อความที่ผู้โจมตีเขียนลงใน log ทำให้ระดับลดลงไม่ได้

Severity comes only from fields the device generates. Text an attacker writes into a log can never lower it.

4 ใช้งานประจำวัน 4: การรวมการ์ดDaily use 4: how events are grouped

  • เหตุการณ์เดียวกันซ้ำกันเป็นการ์ดเดียว พร้อมตัวนับ ×NRepeats of one event are one card with a count ×N.
  • ค่าที่ผู้โจมตีเปลี่ยนได้ (ชื่อผู้ใช้, URL) เก็บเป็น "ตัวอย่าง" สูงสุด 5 ค่า brute force ด้วยชื่อผู้ใช้สุ่มจึงยังเป็นการ์ดเดียวValues an attacker can vary (user names, URLs) are kept as up to 5 samples, so a brute force with random user names stays one card.
  • การสแกนระดับ low จากหลาย IP (เช่น Wazuh 5710) รวมเป็นการ์ดเดียวต่อกฎและเครื่อง ระดับ medium ขึ้นไปแยกตาม IPLow-severity scanning from many IPs (e.g. Wazuh 5710) is one card per rule and host; medium and above stay one card per IP.
  • burst: ถ้าแหล่งหนึ่งสร้างการ์ดใหม่เกิน 120 ใบต่อนาที เหตุการณ์ใหม่ที่ต่างกันจะรวมเป็นการ์ด "burst of distinct events" ใบเดียวBurst: above 120 new cards a minute from one source, further distinct events fold into one "burst of distinct events" card.
  • correlated: IP เดียวกันที่ FortiGate และ Wazuh เห็นภายใน 1 ชม. ทั้งสองการ์ดได้ป้าย correlated และระดับเพิ่ม 1 ขั้น (สูงสุด high)Correlated: the same IP seen by FortiGate and Wazuh within an hour tags both cards "correlated" and raises them one level (at most high).

5 ใช้งานประจำวัน 5: AI อธิบายDaily use 5: Explain (AI)

กด "Explain (AI)" บนการ์ดเพื่อให้โมเดลในเครื่อง (เช่น qwen2.5:3b) อธิบายและแนะนำว่าควรทำอะไร ใช้เวลาประมาณ 23 วินาทีต่อการ์ดบน CPU

Press "Explain (AI)" on a card: a local model (e.g. qwen2.5:3b) explains it and suggests an action, in about 23 s per card on a CPU.

  • AI ทำให้ระดับสูงขึ้นได้อย่างเดียว ไม่มีทางลดระดับThe AI can only raise a card's severity, never lower it.
  • ถ้า AI ยกระดับการ์ดที่อุปกรณ์ให้ระดับ low/info จะขึ้นบนกระดานเท่านั้น ไม่ส่งแจ้งเตือน แม้การ์ดจะเป็น medium เพราะมีข้อความพยายามสั่ง AI ก็ยังนับระดับจากอุปกรณ์ (กันผู้โจมตีหลอก AI ให้ปลุกทีมกลางดึก)If the AI raises a card the device rated low/info, it shows on the board only, with no notification. A card that is medium only because its log tries to instruct the AI still counts as what the device said (so an attacker cannot trick the AI into paging the team).
  • ป้าย "tried to manipulate AI" แปลว่า log มีข้อความพยายามสั่ง AI การ์ดนั้นจะเป็นอย่างน้อย medium และ guard จะไม่ยอมให้ AI ตอบว่าปลอดภัยThe "tried to manipulate AI" badge means the log contains text that tries to instruct the AI. Such a card is at least medium, and the guard never lets the AI call it safe.
  • ในการทดสอบจริง โมเดลถูกหลอกให้ตอบ "benign" 1 ใน 4 ครั้ง และ guard แก้กลับทุกครั้งIn real tests the model was fooled into "benign" once in 4 tries, and the guard overrode it every time.

6 ใช้งานประจำวัน 6: การแจ้งเตือนDaily use 6: notifications

  • บนกระดาน: toast และกระดิ่ง (ระดับ high ขึ้นไปตามค่าเริ่มต้น)On the board: toasts and the bell (high and above by default).
  • ช่องทาง: ntfy, Telegram, LINE (สรุปเป็นรอบ), webhook แต่ละช่องตั้งระดับขั้นต่ำ ช่วงเงียบ และเพดานต่อวันได้Channels: ntfy, Telegram, LINE (digests), webhook. Each has a minimum severity, quiet hours and a daily cap.
  • ช่องทางคลาวด์ได้รับเฉพาะข้อความที่ปิดบังแล้ว: IP, ชื่อเครื่อง, ชื่อผู้ใช้ เป็น token (เช่น HOSTNAME_1) ทดสอบกับการ์ดจริง 30 ใบ ไม่รั่วCloud channels only get masked text: IPs, host and user names become tokens (e.g. HOSTNAME_1). Tested on 30 real cards: no leaks.
  • การดึงข้อมูลครั้งแรกของแต่ละแหล่งเป็นแบบเงียบ: เรื่องที่เปิดอยู่แล้วขึ้นเป็นการ์ด แต่ไม่ส่งแจ้งเตือนThe first pull of each source is quiet: what is already open appears as cards, without notifications.

7 ติดตั้งและตั้งค่า 1: ติดตั้งInstall and configure 1: install

คำสั่งเดียว (Linux) ใช้ Docker ถ้ามี ถ้าไม่มีใช้ Node 22.13 ขึ้นไปพร้อม systemd service:

One command (Linux). It uses Docker if present, otherwise Node 22.13+ with a systemd service:

curl -fsSL https://raw.githubusercontent.com/MONNNNNNNNNNN/kku-netsec-assistant/main/install.sh | sh
  • ตัวช่วยตั้งค่าจะถามทีละข้อ และทดสอบกับระบบจริงทันที: IP ของ FortiGate, Wazuh indexer, Zabbix, โฟลเดอร์ backup, ช่องทางแจ้งเตือน, LLMThe wizard asks one question at a time and tests each answer live: FortiGate IP, Wazuh indexer, Zabbix, backup folder, a notification channel, the LLM.
  • ผลลัพธ์: netsec.json (ไม่มีรหัสผ่านในไฟล์) และ secrets.env (สิทธิ์ 600) รหัสผ่าน admin แสดงครั้งเดียวIt writes netsec.json (no secrets inside) and secrets.env (mode 600), and shows the admin password once.
  • รันซ้ำ = อัปเกรด เก็บ config และข้อมูลไว้ ใส่ --reconfigure ถ้าต้องการตอบคำถามใหม่Running it again upgrades and keeps config and data; add --reconfigure to answer the questions again.
  • ตัวเลือก: sh -s -- --docker หรือ --node, --dir /srv/netsec-board, --non-interactive (ใช้ตัวแปร NETSEC_SETUP_*)Options: sh -s -- --docker or --node, --dir /srv/netsec-board, --non-interactive (with NETSEC_SETUP_* variables).

วัดจริง: ติดตั้ง 10 วินาที การ์ดจริงใบแรก 3.6 วินาทีหลังเริ่ม

Measured: install in 10 s, first real card 3.6 s after start.

8 ติดตั้งและตั้งค่า 2: FortiGateInstall and configure 2: FortiGate

FortiGate ส่ง syslog มาที่กระดาน (แนะนำ TCP) บน FortiGate CLI:

FortiGate sends syslog to the board (TCP recommended). On the FortiGate CLI:

config log syslogd setting
    set status enable
    set server "<board IP>"
    set mode reliable
    set port 5514
    set format rfc5424
end
  • ใส่ IP ของ FortiGate ใน sources.syslog.allow ผู้ส่งอื่นถูกทิ้งPut the FortiGate's IP in sources.syslog.allow; any other sender is dropped.
  • UDP ปลอม IP ต้นทางได้และหายได้ ถ้าใช้ TCP ให้ตั้ง "udp": falseUDP sender addresses can be forged and packets can be lost: with TCP, set "udp": false.
  • backup config: ให้งาน backup เดิมเขียนไฟล์ .conf ลงโฟลเดอร์ แล้วเปิด sources.configdropConfig backups: let your existing backup job write .conf files into a folder and enable sources.configdrop.

9 ติดตั้งและตั้งค่า 3: WazuhInstall and configure 3: Wazuh

กระดานอ่านจาก Wazuh indexer (พอร์ต 9200) ด้วย user ที่อ่านได้อย่างเดียว สคริปต์อยู่ใน repo บนเครื่อง Wazuh all-in-one ให้ clone แล้วรันด้วย sudo ก่อนติดตั้งกระดาน:

The board reads the Wazuh indexer (port 9200) with a read-only user. The scripts are in the repo: on a Wazuh all-in-one host, clone it and run them with sudo before installing the board:

git clone https://github.com/MONNNNNNNNNNN/kku-netsec-assistant && cd kku-netsec-assistant
sudo sh lab/wazuh-prepare.sh       # read-only user netsec_board_ro; password and CA in /etc/netsec-board/
sudo sh lab/wazuh-heap.sh 4g       # only if the indexer answers HTTP 429 circuit_breaking_exception
  • ตัวช่วยตั้งค่าถามรหัสผ่าน (ดูได้ด้วย sudo cat /etc/netsec-board/wazuh-ro-password) แล้วเก็บไว้ใน secrets.env (0600) ไม่ใช่ใน netsec.jsonThe wizard asks for the password (read it with sudo cat /etc/netsec-board/wazuh-ro-password) and keeps it in secrets.env (0600), not in netsec.json.
  • ตัวติดตั้งคัดลอก CA ของ indexer (Wazuh ใช้ CA ที่ลงนามเอง) ไปที่ certs/wazuh-root-ca.pem ข้าง netsec.json ถ้าอ่านได้ ตัวช่วยตั้งค่าจะเสนอไฟล์นี้ให้ ใน Docker กระดานเห็นเฉพาะโฟลเดอร์ certs/ นี้ ถ้าคัดลอกเองให้รัน installer ด้วย sudo หรือ sudo cp /etc/netsec-board/wazuh-root-ca.pem certs/The installer copies the indexer CA (Wazuh uses a self-signed CA) to certs/wazuh-root-ca.pem next to netsec.json when it can read it, and the wizard offers that file. In Docker the board sees only this certs/ folder; otherwise copy it yourself: sudo cp /etc/netsec-board/wazuh-root-ca.pem certs/.
  • เลือกอย่างใดอย่างหนึ่ง: pull (ค่าเริ่มต้น) หรือ push ผ่าน integration (deploy/custom-netsec-board.py) ถ้าเปิดทั้งสองแบบ เหตุการณ์จะถูกนับซ้ำ (check จะเตือน)Use one of: pull (default) or push through the integration (deploy/custom-netsec-board.py). With both, events count twice (check warns).
  • Wazuh ส่ง alert เข้า indexer ผ่าน Filebeat ถ้า Filebeat หยุด กระดานจะไม่เห็น alert ใหม่Alerts reach the indexer through Filebeat: if Filebeat is stopped, the board sees no new alerts.

วัดจริงกับ Wazuh 4.14.9: ดึงครบทุก alert, ไม่ซ้ำหลัง restart, alert ถึงกระดานใน 13 วินาที (pull) หรือ 1.3 วินาที (push)

Measured on Wazuh 4.14.9: every alert fetched, no duplicates after a restart, alert to card in 13 s (pull) or 1.3 s (push).

  • สร้าง user ที่อ่านได้อย่างเดียว (User role, สิทธิ์ read บน host group ที่ต้องการ) และสร้าง API token ให้ user นั้นCreate a read-only user (User role, read on the host groups you want) and an API token for it.
  • pull: ใส่ URL และ token ใน sources.zabbix ตัวช่วยตั้งค่าตรวจให้ และบอกถ้า web server ตัด header Authorization ทิ้งPull: put the URL and token in sources.zabbix; the wizard checks it and tells you if the web server strips the Authorization header.
  • push: สร้าง media type แบบ Webhook จาก deploy/zabbix-media-webhook.js ตั้งให้ Enabled (สร้างผ่าน API จะถูกปิดไว้) แล้วเพิ่ม action ทั้ง problem และ recoveryPush: create a Webhook media type from deploy/zabbix-media-webhook.js, make sure it is Enabled (one created through the API starts disabled), and add an action for problem and recovery.

วัดจริงกับ Zabbix 7.0.32: problem, recovery และการเกิดซ้ำถึงกระดานใน 3-6 วินาที ทั้ง pull และ push

Measured on Zabbix 7.0.32: problem, recovery and recurrence reach the board in 3-6 s, both pull and push.

11 ติดตั้งและตั้งค่า 5: ปรับระดับให้เข้ากับองค์กรInstall and configure 5: tuning severity

severityOverrides ใน netsec.json จับคู่ด้วย regex บน field ที่อุปกรณ์สร้างเท่านั้น ข้อความใน log จึงสั่งกฎเหล่านี้ไม่ได้

severityOverrides in netsec.json match regexes on device-generated fields only, so log text can never trigger them.

"severityOverrides": [
  { "label": "config changes", "source": "fortigate", "match": { "logdesc": "^Configuration changed$" }, "severity": "high" },
  { "label": "core servers", "source": "wazuh", "match": { "agent.name": "^core-" }, "raise": 1 },
  { "label": "server VLAN", "source": "fortigate", "match": { "dstip": "cidr:10.20.0.0/16" }, "raise": 1 }
]
  • severity ตั้งระดับตายตัว (กฎแรกที่ตรงชนะ) raise เพิ่มระดับ (บวกกันได้, สูงสุด critical) เหตุการณ์ที่ถูกตั้งธงพยายามหลอก AI ไม่ต่ำกว่า mediumseverity sets a level (the first matching rule wins); raise adds levels (they add up, at most critical). An event flagged for manipulating the AI never goes below medium.
  • ค่าอื่นที่ปรับได้: board.rearmAfterHours (24), board.autoResolveAfterHours ({"info":24,"low":24,"medium":72}), board.newCardsPerMinute (120), sources.wazuh.perSourceCardsFrom ("medium"), sources.<name>.minSeverity ("low")Other knobs: board.rearmAfterHours (24), board.autoResolveAfterHours ({"info":24,"low":24,"medium":72}), board.newCardsPerMinute (120), sources.wazuh.perSourceCardsFrom ("medium"), sources.<name>.minSeverity ("low").
  • หลังแก้ config รัน node cli/board.js check เพื่อตรวจกฎทุกข้อAfter editing, run node cli/board.js check: it validates every rule.
